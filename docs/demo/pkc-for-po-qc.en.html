PKC · Product Knowledge Compiler

Your product handbook,
written from the code.

PKC reads your system's source code and turns it into a plain-language knowledge base. Then you just ask an AI assistant: “How does this feature work?”, “Who is allowed to do this?”, “Which test cases do I need?”

Why?

The truth about how the product behaves lives in the code, and not everyone can read code.

📚

Docs get stale

Specs describe what was planned. The code is what actually runs.

🧑‍💻

Devs are busy

“Quick question about the rules…” turns into a 30-minute interruption.

🔍

Edge cases hide

Permissions, validations and error paths are easy to miss when writing test cases.

How PKC works

Four steps, fully automatic. Building the handbook uses no AI and sends no code anywhere.

🗺️ Look around

Maps the system first: which apps exist, which parts are tests, third-party libraries or build output. The noise gets skipped.

📖 Read carefully

Reads only your team's own code: screens, APIs, rules, checks and data.

🔗 Connect the dots

Links each button on a screen to the API behind it, then to the rules and data changes it triggers.

📝 Write the handbook

Produces feature and workflow pages in plain language, including a clear list of what it could not prove.

How it plugs into AI

The AI reads the handbook, not the source code, and opens only the pages your question needs.

Good to know

✅

What the code does

Answers describe what the system actually does today, not what a spec says it should do.

⚠️

Honest gaps

Anything it couldn't analyze is listed and counted, so you know when to double-check with the team.

🔒

No code in answers

The knowledge base holds no source files, only short rule conditions. Answers are written in business language.
