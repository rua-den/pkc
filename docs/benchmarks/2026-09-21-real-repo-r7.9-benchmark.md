## Release blocker discovered: transitive helper mutation over-promotion

The modern Angular benchmark exposed a wrong causality promotion in generated PO-facing knowledge.

`AppDbContext.SaveChangesAsync()` calls `SetTimestamps()`. `SetTimestamps()` iterates only tracked entries whose EF state is `Modified`, then conditionally updates either `User.UpdatedAt` or `Contact.UpdatedAt` depending on the runtime entity type.

Current feature-candidate traversal includes reachable helper conditions/mutations, and `GroundedKnowledgeSynthesizer.IsKnowledgeMutation(...)` promotes transitive member mutations without proving that the helper's mutated runtime object is actually the endpoint's affected entity.

This causes incorrect workflow claims such as:

```text
Auth Signup:
- Sets user.UpdatedAt to DateTime.UtcNow.
- Sets contact.UpdatedAt to DateTime.UtcNow.

Contacts Store:
- Sets user.UpdatedAt to DateTime.UtcNow.
- Sets contact.UpdatedAt to DateTime.UtcNow.
```

Those flows call `DbSet.Add(...)`, so the newly added entity is `Added`, not `Modified`; the timestamp helper does not perform those claimed mutations. The Contact Store path also does not modify the loaded current User.

The contamination is not isolated: both timestamp mutations are currently surfaced in 10 generated workflows each. Some update workflows legitimately modify one entity type, but the unrelated entity mutation is still over-promoted.

Classification:

```text
WRONG CLAIM / MUTATION-CAUSALITY LEAK
release blocker
```

This takes priority over adding broader R7.9 syntax support or beginning R7.10 implementation.

## 2026-09-22 blocker closure

The transitive-helper mutation-causality release blocker above is now **CLOSED**.

Accepted implementation checkpoint:

```text
67624944da27ff1f1f5a1154018a255aae11d1fe
fix: avoid capturing mutation receiver out parameter
```

The generic authority rule now keeps raw mutation evidence but marks mutations whose receiver is introduced by a runtime pattern variable (for example `entry.Entity is User user`) as crossing an unproven caller-object causality boundary. Such mutations are not promoted into a transitive workflow candidate unless that causality can be proven. Ordinary local/domain-object transitive mutations remain eligible, so legitimate effects such as the PokeTrade stock/status mutations are preserved.

Regression coverage locks all three boundaries:

```text
runtime pattern-selected receiver → raw evidence retained, workflow promotion denied
ordinary local/domain receiver     → transitive mutation retained
self-owned domain mutation         → transitive mutation retained
```
