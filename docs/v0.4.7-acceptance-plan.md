## D / R7.10 — current formal gate

R7.10 must fail closed when Angular component-import topology is not sufficiently proven because lexical child interpolation under a component host is not necessarily directly rendered output.

Rereview #17 found that the unsupported-indirection guard recognized the semicolon form but missed equivalent compile-valid TypeScript ASI scalar aliases.

Regression-first implementation then proved additional valid variants: LF, lone CR, U+2028, U+2029 and a line terminator inside a block comment. Rather than encode a partial ASI grammar, final production conservatively recognizes unsupported alias/indirection from:

```text
const|let|var <identifier> = <identifier>
```

without requiring a particular source terminator.

If that prefix continues into a call/member/binary or other expression shape that PKC has not proven as supported component-import topology, conservative fail-close is acceptable. The authority filter must never invent render/visibility proof from ambiguous indirection.

Ordinary supported direct/local-array framework imports remain positive-regression protected.

## E0 — Repository Discovery + bounded run readiness — PREPARED / LOCKED

A private mixed legacy enterprise repository showed the current whole-root product path can become operationally impractical before useful output; one observed run reached roughly 9 GB RAM. This is design evidence, not a universal numeric threshold.

E0 must solve the structural cause: deterministic repository discovery, scope reduction and bounded execution.

### Required sequence once unlocked

```text
RD1 inventory + safe exclusion
→ RD2 application boundaries + ownership
→ RD3 vendor/custom frontend classification
→ RD4 runtime/plugin provenance
→ RD5 deterministic ScanPlan
→ RD6 scoped/bounded semantic execution
→ RD7 coverage + observability + plan-only inspection

→ prove pkc run practically produces .pkc/workspace
```

Run these sequentially.

### E0 required properties

- deterministic repository inventory;
- discovery before expensive C#/frontend semantic scanning;
- only strongly proven generated/restorable areas auto-exclude;
- names such as `legacy`, `vendor`, `plugins`, `themes`, `Scripts`, `Content`, `old` never exclude by themselves;
- application/component boundaries and shared ownership are explicit;
- tests never create production authority;
- first-party runtime/shared, third-party runtime, modified vendor, infrastructure, tests, generated/restorable and UNKNOWN stay distinguishable;
- third-party runtime remains visible without deep-scanning internals;
- modified vendor receives only narrow deterministic first-party carve-outs;
- runtime/plugin edges require deterministic provenance;
- ambiguous shapes stay UNKNOWN/fail-closed;
- `scan-plan` is stable, inspectable and privacy-safe;
- semantic scanners execute only planned scopes/application waves;
- UNKNOWN is not silently discarded;
- coverage cannot claim READY when required areas are omitted/unsupported;
- a plan-only/discovery path exists before expensive semantic execution;
- private validation sanitizes all evidence;
- the approved demo repository ultimately produces `.pkc/workspace` practically.
