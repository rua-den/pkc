## Product-knowledge invariants

Keep these evidence classes distinct:

```text
business conditions
value lineage / provenance
mutation / causality
```

Authority rule:

```text
deterministically proven observable behavior
→ may become authoritative product-behavior knowledge

deterministic implementation evidence without full authority
→ retain as lower-authority lineage / provenance / mutation / causal evidence

unsupported inference
→ fail closed; do not invent
```

Same/similar names are never sufficient proof. Conservative authority downgrade must not erase deterministic evidence.

## Product Owner acceptance questions

Generated portable knowledge must answer these questions from evidence or explicitly say the answer is not proven:

1. Where did this value originally come from?
2. If the upstream value changes later, does the existing downstream value change automatically?
3. What code path can change this value after creation?
4. Was this value directly copied or computed?
5. What was the last observed source before a supported persistence/return boundary?
6. What backend conditions and frontend conditions jointly determine whether an item/value is visible?
7. How does a value travel through backend → DTO/projection → API → frontend composition?
8. If authority is incomplete, what lineage or causal evidence is still deterministically known?

Raw fact existence alone is insufficient; portable knowledge must support a PO-level answer.

## Canonical lineage semantics

| Semantic | Required meaning |
| --- | --- |
| `copy` | Direct assignment without modeled computation. |
| `snapshot` | Stored copied/derived value captures a point in time; later upstream changes do not automatically mutate it. |
| `derivation` | Downstream value is computed from one or more proven inputs. |
| `reference/dynamic` | Downstream read resolves from upstream state at read time. |
| `override` | Later write supersedes a previously sourced value without erasing original origin. |
| `mutation` | A code path writes downstream value/state after prior state existed. |

`copy` and `snapshot` are not synonyms; `override` must not rewrite history.
