## Blocker found only after source cross-check

The frozen blind output contained suspicious root routes such as:

```text
/Restart
/Enabled
/Restore
```

Source inspection showed that `BaseJellyfinApiController` declares:

```csharp
[ApiController]
[Route("[controller]")]
```

and controllers such as `SystemController`, `QuickConnectController`, `BackupController` and `ScheduledTasksController` rely on that inherited controller route.

ASP.NET Core application-model behavior was checked against framework source: route attributes are resolved by walking from the derived controller toward base types until the nearest class that defines controller route attributes. A derived explicit `[Route("")]` therefore intentionally overrides the inherited route rather than composing both.

The previous PKC controller scanner only inspected route attributes declared directly on the current class. That caused false effective-route claims.

## Regression-first correction

Red regression:

```text
commit: 204b1b3e1d16d41f5c7feee2322d2e16c316b681
run:    34790695916 — FAIL as expected
```

The regression requires a derived `SystemController` to resolve inherited `[Route("[controller]")]` as `System/Restart`.

Protective override regression:

```text
commit: f1c62410706853c047ffbbcfcde6be9a6e458867
```

This separately proves that a derived `[Route("")]` keeps `LibraryController` actions root-based instead of incorrectly producing a `/Library/...` prefix.

Generic fix:

```text
commit: 2a9ec6c00d46ebf907d543837e6e270d85c240e1
```

The fix adds deterministic MVC controller-route enrichment. It:

- walks current type to base types;
- uses the nearest type that declares a controller route;
- stops on an explicit empty route;
- resolves `[controller]` / `[action]` tokens conservatively;
- composes controller/action routes only when justified;
- omits an unprovable exact `fullRoute` instead of inventing one;
- contains no Jellyfin/path/repository special case.

## Representative source cross-check

The source cross-check sampled the critical blind-question areas rather than only the route blocker.

### User/auth/token

`UserController` confirmed grounded behavior around elevated operations, missing users, token revocation, password changes, current-password verification, cross-user administrator guards, last-administrator / last-enabled-user safeguards, user policy/config updates, user creation and local-network behavior in password reset flows.

### Session/device control

`SessionController` confirmed root-based session listing and remote browse/play/playstate/system/general/message commands, controlling-user assignment, additional-user changes and capability reporting.

### Playback/transcoding

`PlaystateController` confirmed authorization, played/unplayed updates, session lookup, playback start/progress/stopped behavior, playback ping and transcoding-job interaction.

### Configuration/tasks/admin

`ConfigurationController` confirmed elevated writes, full and named configuration mutation, null-deserialization failure and branding/config updates.

`ScheduledTasksController` confirmed inherited `/ScheduledTasks` routing, elevated access, list/get/start/stop/update operations, missing-task handling and trigger mutation.

### Library/download

`LibraryController` confirmed explicit root routing, `Items/{itemId}/Download`, download policy enforcement, missing-item handling and download eligibility behavior.

### Item refresh/providers

`ItemRefreshController` confirmed elevated item refresh, missing-item handling, refresh-option construction and provider refresh queuing.

`ItemLookupController` confirmed remote provider search, external-ID information, elevated search-criteria application, missing-item handling, provider-ID mutation and full provider refresh.

After the generic route correction, this coding-thread cross-check found no blocker-class false claim in the ten frozen critical product/system questions. That is an internal candidate assessment only; independent review remains authoritative.

## Review warnings intentionally left open

### W3 — multiple HTTP method attributes

Jellyfin `SystemController.PingSystem` exposes both GET and POST attributes. Current endpoint extraction records only the first HTTP attribute, so portable knowledge shows GET `/System/Ping` but not the duplicate POST operation.

Internal classification: non-blocking because the same method behavior is exposed by both verbs. Independent review must challenge this classification.

### W4 — feature-level promotion

Some feature pages can still say `No grounded information available yet` for observed business rules while linked workflow evidence contains meaningful authorization, mutation or validation semantics. Critical questions were answerable, but promotion/abstraction quality remains reviewable.

### W5 — large pack

The Jellyfin package contains 504 canonical Markdown files. The hierarchy is navigable, but signal-to-noise at this scale remains a review concern.

Existing warnings W1 (claim-level portable provenance) and W2 (durable blind-review reproducibility) also remain open follow-up concerns.
