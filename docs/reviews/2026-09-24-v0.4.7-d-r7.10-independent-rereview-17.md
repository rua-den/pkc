## Blocker — semicolonless scalar alias bypasses fail-closed import indirection

The existing supported negative regression uses:

```ts
import { SHARED_IMPORTS } from './shared-imports';

const IMPORTS = SHARED_IMPORTS;

@Component({
  imports: [IMPORTS],
  template: `<div ext-shell>{{ displayPrice }}</div>`
})
export class PriceComponent {}
```

The production filter detects that unsupported scalar alias with:

```text
\b(?:const|let|var) <name> = <target> \s* ;
```

so the terminating semicolon is part of the recognition boundary.

TypeScript automatic semicolon insertion permits the semantically equivalent form:

```ts
import { SHARED_IMPORTS } from './shared-imports';

const IMPORTS = SHARED_IMPORTS

@Component({
  imports: [IMPORTS],
  template: `
    @if (isAllowed) {
      <div ext-shell>{{ displayPrice }}</div>
    }
  `
})
export class PriceComponent {
  isAllowed = true;
  displayPrice = 42;
}
```

Local parser/compiler verification in this review environment:

```text
tsc 5.8.3 --noEmit --target ES2022 --experimentalDecorators  PASS
```

Compiling the semicolonless and semicolon forms produced equivalent JavaScript for the alias/decorator sequence; the emitted JavaScript contains:

```js
const IMPORTS = SHARED_IMPORTS;
```

Therefore omission of the source semicolon is not an unsupported TypeScript construct or a runtime distinction.

## Why the current pipeline lets authority survive

The counterexample uses the same indirect external-component shape already covered by the accepted negative regression:

```ts
// shared-imports.ts
import { ExternalShell } from '@vendor/ui';
export const SHARED_IMPORTS = [ExternalShell];
```

with the package linked through `node_modules` to the external-package fixture outside the repository root.

On exact `96205a9a...`:

1. `AngularComponentImportClosureAuthorityFilter` can propagate external-component risk to `SHARED_IMPORTS` through the local file/import closure.
2. That filter only expands supported constant **array** aliases; it does not promote scalar `IMPORTS = SHARED_IMPORTS` into the risk set.
3. `AngularUnresolvedExternalComponentImportAuthorityFilter` does not rescue this path because the component source has only the local import; the external package import is in the helper file.
4. `AngularComponentProjectionAuthorityFilter` cannot prove the outside-root linked package selector for this indirect component source; the direct rejected-link fail-closed marker is attached only where the rejected external package import and component template are co-located.
5. `AngularUnsupportedComponentImportIndirectionAuthorityFilter` is the intended final fail-closed boundary for the scalar alias, but its `ScalarAliasRegex` requires `;`. The semicolonless alias is therefore absent from `scalarAliases`.
6. `imports: [IMPORTS]` does not overlap the unsupported alias set, so the authoritative `ui-member-render` is not rejected by that filter.
7. The later SVG/visibility stages are downstream of this authority decision and do not establish the missing component-import proof.

The existing regression `Scalar_alias_of_indirect_external_component_imports_fails_closed` contains `const IMPORTS = SHARED_IMPORTS;`, so it does not cover this compile-valid spelling.
