## New counterexample

Angular legacy template support can make `<template>` an inert template fragment:

```json
{
  "angularCompilerOptions": {
    "enableLegacyTemplate": true
  }
}
```

Compile-valid/runtime-valid template:

```html
<template>
  @if (displayPrice > 0) {
    <strong>{{ displayPrice }}</strong>
  }
</template>
```

The `<template>` fragment is not an active rendered subtree. It is semantically the legacy template container counterpart of `<ng-template>`.

## False authority at `1fc4d212...`

The R7.9 render-authority boundary recognized inert `<ng-template>` but not legacy `<template>`. Therefore the simple interpolation inside the inert legacy fragment could remain an authoritative `ui-member-render`.

Because the interpolation sits textually under a supported `@if`, downstream visibility enrichment could then attach the frontend condition and exact-ID composition could overstate both:

```text
R7.9: API field reaches a rendered UI value
R7.10: backend predicate + frontend @if jointly determine visible rendered value
```

The runtime truth is that this fragment is inert and does not itself provide visible rendered output.

## Violated proof boundary

R7.9 requires an **authoritative active rendered text interpolation**. The defect allowed text inside an inert Angular template fragment to satisfy that authority boundary.

R7.10 composes only from accepted R7.9 render identity, so once the R7.9 terminal is false, any downstream joint-visibility authority built from it is also false.

This is not a complaint that PKC lacks general Angular support. It is a concrete false-positive authority path from a compile-valid/runtime-valid project configuration.

## Required repair

Regression-first minimum generic repair:

1. Reproduce the legacy `<template>` false-positive with `enableLegacyTemplate=true`.
2. Treat legacy `<template>` and `<ng-template>` as the same inert template-fragment boundary for render authority.
3. Keep a positive safeguard proving a closed inert fragment does not suppress later active text.
4. Do not broaden unrelated CSS/runtime/DOM semantics.
5. Run focused, related, full, real-project, parity and benchmark gates.
