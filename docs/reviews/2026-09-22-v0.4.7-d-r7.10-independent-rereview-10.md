## Counterexample class 1 — SVG `<defs>` content is not directly rendered

Angular component templates support SVG and interpolation. This template shape is valid:

```html
@if (isAllowed) {
  <svg>
    <defs>
      <text>{{ displayPrice }}</text>
    </defs>
  </svg>
}
```

SVG `<defs>` stores graphical definition content for later reference; its child content is not directly rendered where defined.

On `1bc67e62...`, `AngularResponseBindingScanner` could still observe the exact simple `{{ displayPrice }}` interpolation. `AngularRenderedMemberAuthorityFilter` modeled comments, tag/attribute interpolation, inert Angular templates, `ngNonBindable`, hidden/CSS presentation suppression and `<style>`, but did not model SVG definition ancestry. The interpolation could therefore receive:

```text
renderAuthority = active-component-inline-template+exact-simple-interpolation
```

The enclosing supported `@if` could then add `ui-member-visibility`, allowing downstream R7.9/R7.10 claims that the API value is rendered/visible when `isAllowed` even though this occurrence is definition content rather than directly presented output.

## Counterexample class 2 — SVG `<symbol>` content is not directly rendered

The same direct-render issue exists for a symbol definition:

```html
@if (isAllowed) {
  <svg>
    <symbol id="price-symbol">
      <text>{{ displayPrice }}</text>
    </symbol>
  </svg>
}
```

`<symbol>` defines reusable graphics; the symbol itself is not directly rendered as a visible instance. A later `<use>` can instantiate it, but that runtime/reference path is outside the currently proven R7.9 boundary.

## Violated proof boundary

R7.9 requires an authoritative active visible/directly-rendered Angular text interpolation. The predecessor proved that an interpolation occurrence was active Angular template syntax but did not prove that the SVG container directly presents that occurrence.

R7.10 composes from the accepted R7.9 render fact, so an over-authoritative render fact can contaminate joint visibility even when all exact IDs are internally consistent.

This blocker does **not** demand a complete SVG renderer or `<use>` graph. Unsupported indirect rendering may remain unproven; the concrete problem is that non-direct definition content was being promoted instead of failing closed.
