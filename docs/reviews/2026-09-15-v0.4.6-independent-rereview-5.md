## Remaining B6.4 blocker — projector side effects after a proven copy

The same-type projector proof still establishes only that every predicate-relevant member has at least one direct `output.Member = input.Member` assignment somewhere in the object initializer.

It does **not** prove that later initializer writes cannot mutate a previously copied predicate-relevant member.

`IsDirectlyStoredMember` validates the predicate-relevant member itself, but the proof does not require all other initializer targets to be side-effect free.

### Compile-valid counterexample

```csharp
public sealed class Card
{
    public bool IsPublished { get; set; }

    private bool _blocked;

    public bool Blocked
    {
        get => _blocked;
        set
        {
            _blocked = value;
            IsPublished = false;
        }
    }
}

private readonly List<Card> _cards =
[
    new Card { IsPublished = true, Blocked = false }
];

public IReadOnlyList<Card> GetCards() =>
    _cards
        .Where(card => card.IsPublished)
        .Select(CloneCard)
        .ToArray();

private static Card CloneCard(Card card) => new()
{
    IsPublished = card.IsPublished,
    Blocked = card.Blocked
};
```

Observable behavior:

1. `Where` sees the source card with `IsPublished == true`, so it passes.
2. `CloneCard` first copies `IsPublished = true`.
3. The later `Blocked = card.Blocked` assignment invokes the custom `Blocked` setter on the output object.
4. That setter changes the output object's `IsPublished` to `false`.
5. The returned clone therefore does **not** satisfy the predicate that PKC may still promote as an authoritative returned-item inclusion rule.

Current proof path can still succeed because:

```text
requiredMembers = [Card.IsPublished]
Card.IsPublished is an auto-property                   → accepted stored member
initializer contains IsPublished = card.IsPublished   → direct-copy proof succeeds
Blocked assignment is not a required predicate member → its setter semantics are never checked
```

The synthesizer can therefore still emit:

```text
Includes items from `_cards` only when `card.IsPublished`.
```

for a returned sequence containing a clone whose `IsPublished` is false.

That is a blocker-class false Product Owner claim.

## Required fix property

Do not special-case `Blocked` or the fixture. The generic boundary must be:

```text
predicate dependencies completely proven
+ required predicate state copied
+ the entire supported projector path proven unable to invalidate that state
→ projection may preserve authoritative Where semantics

otherwise
→ observed-only / no authoritative product-level inclusion rule
```

For V0.4.6, conservative rejection is acceptable. A safe implementation may restrict supported object-initializer projector shapes so that unproven custom setters, nested initializer effects, or other writes capable of mutating predicate-relevant output state cause downgrade.

Required focused regression:

```text
Where(card => card.IsPublished)
→ Select(CloneCard)
→ CloneCard directly copies IsPublished
→ a later custom setter changes output.IsPublished
→ no authoritative inclusion rule
```
