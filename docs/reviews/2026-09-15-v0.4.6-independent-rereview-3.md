## B6.4 — BLOCK: arbitrary `Select` does not preserve `Where` output-item semantics

### What improved

The reviewed implementation correctly stops treating arbitrary syntactic containment inside a return expression as observable authority.

Current positive authority is conservative for:

- direct `Any`, `All`, `First*`, `Single*` return values, with parentheses only;
- `Where` returned directly or through a semantic receiver-chain allowlist;
- transformed/negated `Any`/`All` and null/pattern tests around `First*`/`Single*` are downgraded to observed-only;
- arbitrary helper wrapping is not considered proof;
- local/discarded predicates and rejecting guards remain non-authoritative product rules.

This closes the blocker examples from the previous review.

### Remaining defect

`CSharpBusinessPredicateAuthorityFilter.WherePipelineTargets` currently includes both:

```text
System.Linq.Enumerable.Select
System.Linq.Queryable.Select
```

and `IsWhereEffectPreserved` treats any semantically resolved allowlisted receiver-chain invocation as preserving the original `Where` predicate's observable inclusion semantics.

That assumption is false for arbitrary `Select`: projection can replace every filtered source element with another value or another source element that does not satisfy the predicate.

### Reproducible counterexample

Valid C#:

```csharp
private readonly List<Card> _cards =
[
    new Card(IsPublished: false),
    new Card(IsPublished: true)
];

public IReadOnlyList<Card> GetCards() =>
    _cards
        .Where(card => card.IsPublished)
        .Select(_ => _cards[0])
        .ToArray();
```

Runtime behavior:

1. `Where` selects the published second card.
2. `Select` replaces that element with `_cards[0]`.
3. `_cards[0]` is unpublished.
4. The returned list therefore contains an item from `_cards` for which `IsPublished == false`.

Current authority path nevertheless succeeds:

```text
Where                         exact LINQ target
→ Enumerable.Select           allowlisted
→ Enumerable.ToArray          allowlisted
→ businessRuleAuthority=observable
→ observableEffectResolution=semantic-return-value-path
```

The synthesizer can then emit:

```text
Includes items from `_cards` only when `card.IsPublished`.
```

That Product Owner claim is false for the method above.

### Why the existing regression is insufficient

The positive projection regression currently uses an identity selector:

```csharp
.Select(card => card)
```

That specific pipeline preserves the filtered item identity, but production accepts every `Select` selector. The regression proves one safe selector, not the generic production rule.

### Required fix property

Do not special-case the fixture. Establish this generic boundary:

```text
Where predicate
+ every outer operation proven to preserve the predicate's output-item semantics
→ authoritative inclusion rule

otherwise
→ observed-only / lower authority / no product-level inclusion claim
```

For V0.4.6, conservative options include:

- accept `Select` only when the selector is deterministically proven identity-preserving; or
- remove arbitrary `Select` from the preserving allowlist and downgrade non-proven projections.

A future richer model may represent source filtering separately from projection semantics, but current `Includes items from <source> only when <predicate>` wording requires output-item preservation.

Required regression before the fix:

```csharp
_cards
    .Where(card => card.IsPublished)
    .Select(_ => _cards[0])
    .ToArray();
```

The predicate must not produce the authoritative rule:

```text
Includes items from `_cards` only when `card.IsPublished`.
```

Keep the existing identity-projection positive regression green if identity preservation is intentionally supported.
