## Supported derivation shape

The positive fixture uses stored scalar auto-properties in exact target-project semantic context:

```text
service.Price = 100
service.Discount = 10
service.NetPrice = service.Price - service.Discount
return service.NetPrice
```

The proof resolves the exact target and every supported input member. It emits `mechanism=derivation`, retains both input occurrences/member identities, records the exact expression and source location, and marks the computed scalar as a stored snapshot.

Supported expressions are intentionally narrow: straight-line scalar arithmetic over supported auto-properties/literals with modeled built-in arithmetic. This is not a general expression or alias solver.

## Supported override/causality shape

The second positive fixture preserves the accepted A origin chain:

```text
group.Price -> product.Price -> service.Price
```

and then observes:

```text
service.Price = 120m
return service.Price
```

The later write emits separate `mutation-causality` evidence with `causalRole=override`, a reference to the prior proven value fact and the prior observed source when available. It does not replace or rewrite the earlier lineage facts.

Generated knowledge must therefore retain both statements:

```text
original observed origin: group.Price -> product.Price -> service.Price
later override: service.Price = 120m
```

## Terminal-source proof

For a direct supported member return, the analyzer records the current proven value fact immediately before the terminal return. The terminal fact identifies:

```text
returned member identity
source fact id
source mechanism
source fact location
return location
```

This lets portable knowledge distinguish the earliest origin from the last proven source before output. The first slice supports a direct return boundary only; arbitrary persistence APIs and general call/dataflow are not claimed.

## Knowledge-class separation

The implementation preserves the permanent contract:

```text
business conditions
value lineage / provenance
mutation / causality
```

Derivation and terminal-source facts render in `Value lineage`. Override causality renders in `State changes`. None of these facts are promoted into authoritative business Rules merely because they are proven implementation behavior.
