## Blocker 1 — `ngNonBindable` literal interpolation

Counterexample:

```html
@if (isAllowed) {
  <strong ngNonBindable>{{ displayPrice }}</strong>
}
```

Angular `ngNonBindable` disables binding/interpolation processing for the element subtree. Runtime therefore presents literal interpolation syntax instead of the `displayPrice` member value.

The reviewed PKC boundary could still discover the simple interpolation text and promote it as an authoritative `ui-member-render`, allowing downstream R7.9/R7.10 value and visibility authority.

### Violated proof boundary

`ui-member-render.renderAuthority` is intended to prove an active rendered member value. Literal non-bindable text is not such proof.

Expected fail-closed behavior:

```text

→ no rendered UI value terminal for that path
→ no ui-member-visibility for that path

```

## Blocker 2 — quoted attribute `>` defeats tag-boundary heuristic

Counterexample:

```html
@if (isAllowed) {
  <div title="price > {{ displayPrice }}"></div>
}
```

Interpolation occurs inside a quoted attribute value, not rendered text content. HTML permits `>` inside quoted attribute values.

The reviewed `IsInsideHtmlTag` logic used a last-`<` / last-`>` heuristic. The `>` inside the quoted value could make the interpolation appear lexically outside the tag and therefore eligible for visible-text render authority.

### Violated proof boundary

Attribute interpolation is not authoritative visible text interpolation. HTML tag/attribute detection must be quote-aware before granting R7.9 render authority.
