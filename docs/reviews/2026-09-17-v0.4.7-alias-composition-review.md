## P1 — invalidate composition when an alias can write the stored value

Affected code: `src/Pkc.CSharp/CSharpValueLineageEnricher.cs:171`, `:219`–`:243` and `:535`.

The extractor skips an ordinary local alias declaration. Slot keys distinguish local declarations, so assigning `alias.Price` invalidates only that declaration's slot. The predecessor for `product.Price` survives even though both receivers denote the same object.

Compile-valid endpoint body, using ordinary scalar auto-properties:

```csharp
var group = new ProductGroup();
var product = new Product();
var alias = product;
var service = new Service();
group.Price = 100m;
product.Price = group.Price;
alias.Price = 50m;
service.Price = product.Price;
return new Result(group.Price, product.Price, service.Price);
```

The exact source scanned by PKC is compiled and executed first. Its result is **group=100, product=50, service=50**. Nevertheless, generated knowledge composes:

```text
Proven stored lineage chain: `group.Price` → `product.Price` → `service.Price`.
```

The service read receives the alias write's value, not the value copied from the group. Each direct assignment observation remains useful; the composed provenance is false.
