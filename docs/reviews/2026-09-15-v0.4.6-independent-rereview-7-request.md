## Rereview-6 blocker

The prior implementation treated several LINQ operations after `Where` as predicate-semantics-preserving solely because the resolved method target appeared in `WherePipelineTargets`.

Counterexample:

```csharp
public IReadOnlyList<Card> GetCards() =>
    _cards
        .Where(card => card.IsPublished)
        .OrderBy(card => card.IsPublished = false)
        .ToArray();
```

Runtime:

```text
Where evaluates IsPublished == true
→ item passes
→ OrderBy key selector executes
→ selector changes IsPublished = false
→ ToArray returns the same item
→ returned item no longer satisfies the predicate
```

Therefore an authoritative returned-item claim that returned items satisfy `card.IsPublished` is false.

## New implementation boundary

`CSharpBusinessPredicateAuthorityFilter` no longer has one broad unconditional pipeline allowlist.

The production change introduces an audited callback-free preserving subset with exact argument-shape checks.

Zero-argument safe subset:

```text
Enumerable.Reverse
Queryable.Reverse
Enumerable.AsEnumerable
Queryable.AsQueryable
Enumerable.ToArray
Enumerable.ToList
```

Slice subset requiring exact supported single argument shape:

```text
Enumerable.Skip
Queryable.Skip
Enumerable.Take
Queryable.Take
```

The old automatic preservation entries were removed for:

```text
OrderBy
OrderByDescending
ThenBy
ThenByDescending
Distinct
ToHashSet
```

including Enumerable/Queryable variants where applicable.

This intentionally fails closed rather than attempting general callback side-effect analysis.
