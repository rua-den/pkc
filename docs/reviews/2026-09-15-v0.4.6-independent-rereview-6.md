## Remaining B6.4 blocker

The broader `Where` observable-effect proof still treats several LINQ operations as semantics-preserving solely because their resolved method target is in `WherePipelineTargets`.

The unconditional allowlist currently includes delegate-bearing operators such as:

```text
System.Linq.Enumerable.OrderBy
System.Linq.Queryable.OrderBy
System.Linq.Enumerable.OrderByDescending
System.Linq.Queryable.OrderByDescending
System.Linq.Enumerable.ThenBy
System.Linq.Queryable.ThenBy
System.Linq.Enumerable.ThenByDescending
System.Linq.Queryable.ThenByDescending
```

`IsAllowedWherePipelineInvocation()` returns `true` immediately when the semantic target is in that set. It does not prove that the operator's user-supplied selector/comparer is unable to mutate the predicate-relevant item state.

### Smallest compile-valid / behavior-valid counterexample

```csharp
public sealed class Card
{
    public bool IsPublished { get; set; }
}

private readonly List<Card> _cards =
[
    new() { IsPublished = true }
];

public IReadOnlyList<Card> GetCards() =>
    _cards
        .Where(card => card.IsPublished)
        .OrderBy(card => card.IsPublished = false)
        .ToArray();
```

Observable execution:

```text
source card IsPublished == true
→ Where predicate evaluates true
→ OrderBy key selector executes for the selected item
→ key selector assigns IsPublished = false
→ ToArray returns the same Card instance
→ returned Card has IsPublished == false
```

The current authority filter nevertheless walks:

```text
Where
→ OrderBy  [unconditionally accepted by semantic target]
→ ToArray  [accepted]
→ return
```

and may retain the `Where` predicate as observable product-rule authority.

The knowledge synthesizer can therefore emit:

```text
Includes items from `_cards` only when `card.IsPublished`.
```

That statement is false for the returned item state in the counterexample.

This is blocker-class because V0.4.6 is specifically attempting to distinguish an observed local query predicate from a deterministically proven observable Product Owner rule.

## Required generic fix property

Do not classify a pipeline operation as predicate-semantics-preserving merely because its LINQ method name/target is known.

For any allowed operation that can execute user-controlled code during enumeration, such as selectors, key selectors, predicates or comparers:

```text
exact LINQ target proven
+ exact overload/argument shape proven
+ every callback/comparer that can observe or mutate the item is proven unable to invalidate predicate-relevant semantics
→ operation may preserve authoritative Where semantics

otherwise
→ fail closed / observed-only
```

A conservative V0.4.6 fix is acceptable. For example, callback-bearing `OrderBy*` / `ThenBy*` paths may simply stop preserving authority unless callback effects are deterministically proven safe.

The coding pass should audit the rest of `WherePipelineTargets` for overloads that accept user callbacks/comparers rather than fixing only the literal `OrderBy` spelling.

### Required focused regression

Add a regression equivalent to:

```csharp
_cards
    .Where(card => card.IsPublished)
    .OrderBy(card => card.IsPublished = false)
    .ToArray();
```

Generated knowledge must not contain an authoritative inclusion rule claiming returned items satisfy `card.IsPublished`.

A normal non-mutating supported pipeline may remain authoritative only where the implementation has a deterministic preservation proof.
