## Remaining B6.4 blocker

The previously accepted same-type method-group projector path proves the object initializer but does not prove the object constructor is effect-safe.

`IsPredicatePreservingSameTypeMethodGroupProjection()` obtains the returned object creation and validates `IsSafeDirectCloneInitializer(...)`. `IsSafeDirectCloneInitializer()` checks only initializer assignments. `GetObjectInitializer()` accepts both explicit and implicit object creation regardless of constructor arguments or constructor body.

Therefore a constructor can mutate the filtered source item after `Where` has passed but before the supposedly semantics-preserving initializer copies the predicate member.

### Smallest compile-valid / behavior-valid counterexample

```csharp
public sealed class Card
{
    public bool IsPublished { get; set; }
    public bool Blocked { get; set; }

    public Card() { }

    public Card(Card source)
    {
        source.IsPublished = false;
    }
}

private readonly List<Card> _cards =
[
    new() { IsPublished = true, Blocked = false }
];

public IReadOnlyList<Card> GetCards() =>
    _cards
        .Where(card => card.IsPublished)
        .Select(CloneCard)
        .ToArray();

private static Card CloneCard(Card card) => new Card(card)
{
    IsPublished = card.IsPublished,
    Blocked = card.Blocked
};
```

Observable execution:

```text
source card IsPublished == true
→ Where evaluates true
→ Select invokes CloneCard(card)
→ Card(Card source) sets source.IsPublished = false
→ initializer reads card.IsPublished == false
→ clone.IsPublished becomes false
→ ToArray returns clone with IsPublished == false
```

The current projector proof still satisfies its modeled conditions:

```text
projector parameter type == return type == Card
Card is sealed
predicate dependency IsPublished is an auto-property
returned expression directly creates Card
initializer exists
all initializer targets are stored auto-properties
all initializer assignments are exact same-member copies
required predicate member IsPublished is copied
```

No current check rejects the side-effecting constructor.

PKC can therefore retain the authoritative predicate and synthesize:

```text
Includes items from `_cards` only when `card.IsPublished`.
```

That Product Owner statement is false for the returned clone.

## Required generic fix property

Constructor execution belongs inside the same preservation proof as initializer execution.

```text
complete predicate dependency proof
+ projector returns same closed item type
+ object-construction path itself proven effect-safe
+ every initializer write proven direct/safe
+ every required predicate member copied
→ same-type projection may preserve authoritative Where semantics

otherwise
→ fail closed / observed-only / no authoritative inclusion rule
```

For V0.4.6 a conservative boundary is acceptable. The same-type defensive-clone path can require a deterministically inert construction path, for example an implicit/default constructor with no user code, and reject constructor arguments or user-defined constructors unless their effects are explicitly proven safe.

Do not special-case this exact constructor or `Card`/`IsPublished` names.

### Required focused regression

Add a regression equivalent to the counterexample above. Generated knowledge must not contain an authoritative inclusion rule claiming returned items satisfy `card.IsPublished`.

Keep the existing positive defensive-clone regression green only for a construction path whose constructor behavior is deterministically safe.
