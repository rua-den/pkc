## Counterexample class — SVG presentation resources are not direct rendered output

Representative template:

```html
@if (isAllowed) {
  <svg>
    <clipPath id="price-clip">
      <text>{{ displayPrice }}</text>
    </clipPath>
  </svg>
}
```

The same bounded resource class applies to `<mask>`, `<marker>` and `<pattern>` declarations.

Angular component templates accept SVG structure and interpolation. These resource elements define presentation resources used by other SVG elements; their child content is not directly presented at the declaration site.

On `a3334bc...`, `AngularResponseBindingScanner` could still observe the exact simple `{{ displayPrice }}` interpolation. `AngularRenderedMemberAuthorityFilter` suppressed `style`, `defs` and `symbol`, but did not model the additional resource-container ancestry. The interpolation could therefore receive:

```text
renderAuthority = active-component-inline-template+exact-simple-interpolation
```

The enclosing supported `@if` could then add `ui-member-visibility`, allowing downstream R7.9/R7.10 claims that the API value is visibly rendered when `isAllowed`, even though this occurrence belongs to a resource definition rather than direct output.

## Violated proof boundary

R7.9 requires an authoritative active directly-rendered Angular text interpolation. The predecessor proved active Angular interpolation syntax but did not prove that the surrounding SVG resource declaration directly presents the interpolated text.

R7.10 composes from the accepted R7.9 render fact, so an over-authoritative render fact can contaminate joint visibility even when all exact IDs are internally consistent.

This blocker does **not** require a complete SVG renderer, reference graph or browser engine. Unsupported indirect/resource rendering may remain unproven; the concrete defect is promotion of non-direct resource content.
