## Remaining B1 blocker — context roots are stripped without enough proof

### Angular side

`TryCanonicalizeFieldPath()` currently strips Angular paths matching these shapes merely because the fact is tagged as Angular:

```text
<root>.value.<field>
<root>.controls.<field>.value
```

The code does not prove that `<root>` is the form associated with the current UI binding. Therefore an ordinary nested object can be collapsed to the same single field name as a real form field.

Reachable example:

```text
UI required when:
this.domain.value.status === 'Active'

backend required when:
request.Status == Status.Active
```

For an Angular validation fact, current canonicalization removes `this`, then treats `domain.value.status` as form scaffolding and reduces it to `status`. The backend request root is also stripped, producing the same field/value key and allowing `consistent / high` even though PKC has not proven that `domain` is the form that supplies the request field.

This violates the B1 acceptance rule: only equivalence that is deterministically proven may become `consistent / high`.

### Backend side

The same issue exists on the backend. `ParseParameterNames()` collects every endpoint parameter name, and `TryCanonicalizeFieldPath()` strips the first path segment when it matches any of them.

A conditional validation such as:

```text
endpoint parameters:
CreateRequest request, StateTracker tracker

backend guard:
tracker.Status == Status.Active && request.TargetId == null
```

can create a `backend-field-validation` for `TargetId` whose condition is `tracker.Status == Status.Active`. Because `tracker` is an endpoint parameter, current canonicalization strips it to `Status`. That can falsely match a UI condition such as `status === 'Active'`.

The backend validation evidence already carries the validated field root as `parameterName`; that is stronger evidence than the set of all endpoint parameter names and should be used to prevent unrelated service/context parameters from being treated as the request model.

## Required follow-up

Fix this regression-first and keep the scope inside B1.

At minimum add failing tests for:

```text
1. Angular object path is not assumed to be form scaffolding:
   this.domain.value.status === 'Active'
   must not be treated as equivalent to backend request.Status == Status.Active
   unless `domain` is independently proven to be the relevant form root.

2. Unrelated backend endpoint parameter root is not stripped:
   tracker.Status == Status.Active
   must not be treated as request-field condition merely because `tracker`
   is an endpoint parameter.
```

Recommended deterministic rule:

```text
Angular:
strip `<form>.value` / `<form>.controls...value` only when `<form>` is the
known form root for the current binding/evidence.

Backend:
strip the condition root only when it is the proven request/validated-object
root for that backend validation fact (for example its `parameterName`), not
when it is merely any endpoint parameter.
```

If that proof is unavailable, preserve the full path or classify the equivalence as unproven. Do not emit `consistent / high` from guessed context stripping.
