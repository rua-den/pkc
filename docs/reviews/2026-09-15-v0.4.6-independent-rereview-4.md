## B6.4 — BLOCK: tracked members are not the complete predicate dependency set

### What the checkpoint fixes correctly

`Select` is no longer in the unconditional returned-`Where` pipeline allowlist.

The implementation now accepts `Select` only when it proves one of these supported forms:

1. an identity selector whose returned identifier resolves to the selector parameter by Roslyn symbol equality; or
2. a narrow same-type method-group projection whose parameter and return types match, whose type is closed, whose source declaration is available, and whose object initializer directly copies every predicate member discovered by `GetWherePredicateMembers`.

The original re-review-3 counterexample is therefore closed:

```csharp
_cards
    .Where(card => card.IsPublished)
    .Select(_ => _cards[0])
    .ToArray();
```

The focused regression `Non_identity_projection_does_not_preserve_returned_filter_authority` covers that shape.

### Remaining defect

`GetWherePredicateMembers` discovers only `MemberAccessExpressionSyntax` nodes whose receiver is directly the predicate lambda parameter and whose resolved symbol is a field or property.

It does **not** establish that the lambda parameter has no other semantically relevant uses. In particular, it ignores whole-item uses such as:

```text
IsAllowed(card)
card.IsAllowed()
ReferenceEquals(card, other)
operator/custom semantics involving card
other helper calls receiving card
```

If the predicate contains at least one direct stored-member access, `requiredMembers.Count` is non-zero and the same-type projector can still be accepted after copying only those tracked members.

The business-predicate extractor, however, stores the **entire lambda body** as the predicate expression, and the synthesizer renders the entire expression as the authoritative inclusion rule. This creates a mismatch between what preservation is proven for and what the Product Owner claim says.

### Reproducible counterexample

```csharp
public sealed class Card
{
    public bool IsPublished { get; init; }
    public bool Blocked { get; init; }
}

private readonly List<Card> _cards =
[
    new() { IsPublished = true, Blocked = false }
];

public IReadOnlyList<Card> GetCards() =>
    _cards
        .Where(card => card.IsPublished && IsAllowed(card))
        .Select(CloneCard)
        .ToArray();

private static bool IsAllowed(Card card) => !card.Blocked;

private static Card CloneCard(Card card) => new()
{
    IsPublished = card.IsPublished,
    Blocked = true
};
```

Runtime behavior:

1. the source card satisfies `card.IsPublished && IsAllowed(card)` because it is published and not blocked;
2. `CloneCard` preserves `IsPublished` but changes `Blocked` to `true`;
3. the returned clone therefore does **not** satisfy `IsAllowed(clone)`;
4. the returned item does not preserve the full `Where` predicate semantics.

Current authority reasoning can nevertheless accept the projection:

```text
GetWherePredicateMembers
  → sees direct card.IsPublished
  → does not model IsAllowed(card)
  → requiredMembers = { IsPublished }

CloneCard
  → Card -> Card
  → sealed type
  → single object initializer
  → IsPublished = card.IsPublished proven
  → Blocked rewrite is not rejected because Blocked was never collected

result
  → Select treated as item-semantics preserving
  → Where remains businessRuleAuthority=observable
```

The stored predicate expression is still the full:

```text
card.IsPublished && IsAllowed(card)
```

so knowledge synthesis can emit:

```text
Includes items from `_cards` only when `card.IsPublished && IsAllowed(card)`.
```

That authoritative Product Owner claim is false for the returned clone.

This violates the V0.4.6 authority boundary:

```text
predicate semantics proven
+ every outer operation proven to preserve the relevant observable semantics
→ authoritative Product Owner rule

otherwise
→ observed-only / lower authority / no product-level rule
```

### Required fix property

Do not special-case `IsAllowed` or the fixture.

For the same-type method-group projection path, PKC must prove that every semantically relevant use of the predicate source parameter is covered by its preservation model. If the parameter is used in an unsupported/unmodeled way, projection preservation must fail conservatively.

A sufficient V0.4.6 boundary is:

```text
all source-parameter dependencies are proven direct stored-member reads
AND every such member is directly preserved by the projector
→ same-type projection may preserve Where authority

otherwise
→ observed-only / no authoritative inclusion rule
```

Examples that should conservatively downgrade unless separately modeled:

```text
helper(card)
card.SomeMethod()
ReferenceEquals(card, ...)
custom/operator semantics involving card
helper indirection for predicate-relevant state
```

Required focused regression before the fix:

```csharp
.Where(card => card.IsPublished && IsAllowed(card))
.Select(CloneCard)
```

where `IsAllowed(card)` depends on `Blocked`, while `CloneCard` preserves `IsPublished` but changes `Blocked` so the returned clone no longer satisfies the predicate.

The existing positive `Select(CloneCard)` regression with a predicate consisting only of directly modeled stored-member reads may remain authoritative if its proof still satisfies the tightened rule.
