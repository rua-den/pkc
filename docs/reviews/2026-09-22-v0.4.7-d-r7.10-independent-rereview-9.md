A new compile-valid/runtime-valid Angular raw-text authority class exists and violates the current bounded render/visibility proof boundary.

## Counterexample class 1 — interpolation-looking text inside `<style>`

Angular component templates may contain `<style>` elements, but Angular does not evaluate interpolation bindings inside style text. This shape is valid template/style content:

```html
@if (isAllowed) {
  <style>
    .price::before { content: "{{ displayPrice }}"; }
  </style>
}
```

On the predecessor, the frontend scanner could still observe `{{ displayPrice }}`. The render-authority filter did not treat `<style>` as a non-bindable raw-text boundary, so that literal CSS text could become an authoritative `ui-member-render` for `displayPrice`. Once promoted, the visibility enricher could attach the enclosing `@if`, allowing downstream R7.9/R7.10 authority from text that is not a rendered Angular member value.

Violated boundary:

```text
authoritative active rendered Angular text interpolation
```

This is not a request for general CSS/browser semantics. It is a narrow framework/template lexical boundary: text inside `<style>` is not Angular interpolation authority.

## Counterexample class 2 — CSS braces corrupt bounded `@if` scope

A separate false-scope shape uses CSS braces inside valid style text:

```html
@if (isAllowed) {
  <style>
    .before::after { content: "{"; }
  </style>
}
<strong>{{ displayPrice }}</strong>
<style>
  .after::after { content: "}"; }
</style>
```

The visible interpolation is outside the actual Angular `@if`. The predecessor `FindMatchingBrace` skipped comments, tags and interpolation regions but did not skip raw style content, so CSS braces could alter its depth count and make the closed `@if` appear to contain the later render.

Violated boundary:

```text
exactly one real enclosing supported Angular @if
```

## Counterexample class 3 — control-looking CSS string text

Style raw text may also contain a literal string such as:

```css
content: "@if (fake) {{";
```

The predecessor searched template text with Angular control regexes without a `<style>` exclusion. Such raw CSS text must not become a real Angular control-flow candidate.

## Required regression

Regression coverage must establish all of the following:

1. interpolation-looking text inside `<style>` does not create authoritative `ui-member-render` or `ui-member-visibility`;
2. CSS braces inside `<style>` cannot extend a closed Angular `@if` over a later visible render;
3. `@if`-looking text inside `<style>` cannot control a later visible render;
4. a normally closed style element before a genuine supported `@if` does not over-filter that positive path.

## Minimum generic repair direction

Repair the raw-style boundary at the two authority layers that currently parse template text:

- render authority must reject member interpolation candidates under `<style>`;
- visibility/control-flow scope parsing must ignore complete `<style>...</style>` text and fail closed on an unterminated style region.

Do not weaken identity checks, R7.9 composition, backend proof or mutation causality.
