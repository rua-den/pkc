## B1 final provenance verification

Re-review 3 identified a reachable false-positive path when a conditional `backend-field-validation` lacked `parameterName`. The correlation layer previously allowed the condition root to be stripped when it matched any endpoint parameter.

The coding follow-up added a real scanner + correlation regression using source equivalent to:

```csharp
public IActionResult Create(CreateTargetRequest request, StateTracker tracker)
{
    if (tracker.Status == Status.Active && this._state.TargetId == null)
    {
        return BadRequest();
    }

    return Ok();
}
```

The test runs the real `CSharpEvidenceScanner`, verifies the generated conditional backend validation has no `parameterName`, merges real frontend evidence, builds cross-stack candidates, runs `ValidationConsistencyCandidateEnricher`, and asserts the correlation cannot be `consistent` or `high`.


The regression failed before the implementation fix, confirming the reported issue was reachable and not fixture-only.

Final fix commit:

```text
5a5fdcb5fdf1a9fb888857791a4757382b86c774
```

The backend condition-field canonicalizer now requires all three proofs before stripping the condition root:

```text
parameterName exists and is non-empty
AND parameterName is an exact-case endpoint parameter
AND condition field root exactly equals parameterName
```

If any proof is absent or contradictory, canonicalization fails conservatively, so the requiredness comparison cannot emit `consistent / high`.

The endpoint parameter-name set is case-sensitive (`StringComparer.Ordinal`), preserving the prior root-identity safety requirement.
