## Finding — invalidate predecessor proof after receiver or opaque state changes

Affected code: `src/Pkc.CSharp/CSharpValueLineageEnricher.cs:143-174` and `:195-200`.

The extractor processes only top-level assignment expressions. If the LHS is not a resolvable property slot, it skips the assignment without invalidating any prior writer. Receiver identity is based on the local/parameter declaration rather than the object currently stored in that variable. Ordinary invocation statements are not processed at all.

Consequently, both of the following compile-valid operations can leave `currentWriter[product.Price]` pointing to the first copy even though the second read no longer receives that copied value.

### Counterexample 1: receiver reassignment

Inside an endpoint with scalar auto-properties and a normal straight-line body:

```csharp
var group = new ProductGroup();
var product = new Product();
var service = new Service();
group.Price = 100m;
product.Price = group.Price;
product = new Product();
service.Price = product.Price;
group.Price = 120m;
return new Result(group.Price, product.Price, service.Price);
```

Executed result: group=120, product=0, service=0. The first write targets the old Product object; the second read uses the new object. No value flowed through both edges.

### Counterexample 2: helper mutation between copies

```csharp
var group = new ProductGroup();
var product = new Product();
var service = new Service();
group.Price = 100m;
product.Price = group.Price;
Mutate(product);
service.Price = product.Price;
return new Result(group.Price, product.Price, service.Price);

// Separate helper method:
// private static void Mutate(Product product) { product.Price = 50m; }
```

Executed result: group=100, product=50, service=50. The service copy reads the helper's value, not the earlier group copy.

In both cases the actual synthesized `ValueLineage` still contains:

```text
Proven stored lineage chain: `group.Price` → `product.Price` → `service.Price`.
Each edge is a direct scalar auto-property copy stored as a snapshot.
```

`MarkdownKnowledgeRenderer` places these strings directly into the Value lineage section. Although the individual assignment observations remain useful, their asserted composition is false.

## Required repair boundary

Process relevant statements in execution order and invalidate predecessor/composition proof when a receiver changes or an operation may write the tracked location. For unsupported effects, a conservative composition barrier is sufficient; no general alias solver or helper-body analysis is required to fix this blocker. Do not retain a proof merely because the local variable's symbol is unchanged.

Keep independently valid direct transfer evidence where possible. Do not solve the false chain by deleting all lineage or weakening the established negative tests. The canonical unmodified straight-line two-edge positive must remain supported.

Unary writes and alias-based writes deserve consideration when defining that same generic invalidation boundary, but they were not separately executed in this review and are not additional claimed blockers. The two executed cases above are sufficient to reproduce the defect.
