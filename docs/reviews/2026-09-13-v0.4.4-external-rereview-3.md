## Remaining B1 blocker — missing backend provenance falls back to endpoint membership

Current backend field-path canonicalization requires a rooted member path and an exact endpoint parameter name. It only binds the root to the validated object **if** `fact.Metadata["parameterName"]` exists.

Therefore this branch remains:

```text
conditional backend validation fact has no parameterName
+ condition root matches any endpoint parameter
→ root is stripped
→ condition may be treated as request-state evidence
```

That fallback is broader than the deterministic proof requirement.

### Reachable scanner path

`CSharpValidationEvidenceScanner` derives `parameterName` with `FindRootIdentifier(fieldAccess.Expression)`. That helper returns `null` when the missing-value check is rooted in `this`, because `this` is not an `IdentifierNameSyntax`.

A valid source shape is:

```csharp
public IActionResult Create(CreateTargetRequest request, StateTracker tracker)
{
    if (tracker.Status == Status.Active && this._state.TargetId == null)
    {
        return BadRequest();
    }

    return Ok();
}
```

The scanner can emit a conditional `backend-field-validation` with:

```text
field: TargetId
method: Create
condition: tracker.Status == Status.Active
parameterName: <absent>
```

Why it is included:

```text
- `this._state.TargetId == null` is a supported missing-value member-access check.
- `FindRootIdentifier(this._state)` returns null.
- method provenance is still `Create`.
- `BelongsToEndpoint()` accepts the fact by method-name match.
```

The current enricher then sees endpoint parameters `request` and `tracker`. Because `parameterName` is absent, `tracker.Status` passes the endpoint-parameter-root test and `tracker` is stripped.

A UI rule such as:

```text
status === 'Active'
```

can then canonicalize to the same field/value condition as `tracker.Status == Status.Active`, allowing `consistent / high` even though the backend missing-value guard is on `this._state.TargetId`, not the request field.

This is the same B1 authority rule as before: absence of validated-object provenance must not be treated as proof.

## Required follow-up

Keep the fix inside B1 and make it regression-first.

At minimum add an **end-to-end scanner + correlation regression using real C# source** for the reachable case above. Do not rely only on fabricated `EvidenceFact` fixtures.

Required behavior:

```text
conditional backend validation participates in proven cross-stack equivalence
only when its validated-object root is known and proven.

If `parameterName` is absent:
→ equivalence is unproven
→ never emit consistent / high.
```

A minimal conservative implementation is to require non-empty `parameterName` for conditional backend field-path canonicalization, require that value to be an exact endpoint parameter name, and require the condition root to exactly equal it.

Existing positive synthetic tests that currently construct conditional backend validation facts without `parameterName` should be updated to include the provenance that the real supported scanner emits for normal request guards, e.g. `parameterName: "request"`.

The scanner may later be hardened to avoid classifying `this.*` state as request-field validation, but that broader cleanup is not required to close this B1 gate if the correlation layer treats missing provenance conservatively.
