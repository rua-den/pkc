## Why this rereview exists

Independent rereview 9 reopened V0.4.6 because exact `System.Linq.Queryable.<operation>` identity was being treated as sufficient evidence for authoritative Product Owner predicate semantics.

That assumption is unsound because `Queryable` is provider-mediated. A custom `IQueryable<T>` / `IQueryProvider` can retain the expression tree handed to `CreateQuery(...)` while enumeration ignores the predicate.

Rereview 9 supplied a compile-valid/behavior-valid counterexample equivalent to:

```csharp
private readonly IQueryable<Card> _query =
    new IgnoringQuery<Card>(new[]
    {
        new Card { IsPublished = false }
    });

public IReadOnlyList<Card> GetCards() =>
    _query.Where(card => card.IsPublished).ToList();
```

where enumeration can still return `IsPublished == false`.

The old authority model could nevertheless synthesize:

```text
Includes items from `_query` only when `card.IsPublished`.
```

That Product Owner statement is false for the observable returned data.

## Current implementation boundary

The implementation in `c310e89` takes the conservative generic route.

### Direct Queryable predicate target

`CSharpBusinessPredicateAuthorityFilter.GetObservableContext(...)` now returns no observable Product Owner authority for an exact `System.Linq.Queryable` predicate target.

The predicate remains deterministic evidence, but it is downgraded to:

```text
businessRuleAuthority = observed-only
observableEffectResolution = not-proven
```

The associated `contains-condition` relation is rewritten to `observes-predicate`.

### Mixed Enumerable → Queryable returned path

`IsAllowedWherePipelineInvocation(...)` rejects every exact `System.Linq.Queryable.*` pipeline hop before the existing callback-free/projection preservation allowlists.

Therefore an Enumerable `Where` cannot inherit authoritative returned-item semantics through a later unproven Queryable hop such as:

```csharp
_cards
    .Where(card => card.IsPublished)
    .AsQueryable()
    .Take(2)
    .ToList();
```

### Evidence retention

`FeatureCandidateBuilder` now retains `observes-predicate` as behavior evidence.

This is required by the permanent product contract:

```text
business conditions
value lineage / provenance
mutation / causality
```

Failing authoritative proof must downgrade the business rule without deleting deterministic lower-authority evidence.

### Deliberate conservatism

No provider identity proof is implemented in V0.4.6. Consequently even ordinary LINQ-to-Objects `AsQueryable()` chains lose Product Owner authority.

Do not treat this conservative coverage loss as a blocker unless it violates a concrete accepted requirement. Do not restore authority from provider names, benchmark names or expression-text special cases.
