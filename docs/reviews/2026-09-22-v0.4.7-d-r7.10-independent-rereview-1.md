## Blocker 1 — inert `<ng-template>` render authority

Compile-valid Angular shape:

```html
<ng-template>
  @if (displayPrice > 0) {
    <strong>{{ displayPrice }}</strong>
  }
</ng-template>
```

A bare `<ng-template>` defines inert template content. Without instantiation/outlet/embedded-view creation, its interpolation is not a currently rendered visible value. The bounded R7.9 scanner/authority filter could nevertheless retain `{{ displayPrice }}` as an authoritative render, allowing downstream R7.10 visibility composition.

That would create a false PO-facing statement about a value being rendered/visible.

Regression-first repair:

```text
05ad6cb937010702a3fd01d5ef756e31bc4e8d9b
fix: fail closed on inert ng-template renders
```

Current behavior conservatively rejects interpolation under an `<ng-template>` ancestor. This can produce false negatives for dynamically instantiated templates, which is acceptable until PKC proves that runtime/template instantiation boundary.

## Blocker 2 — HTML-comment interpolation

Compile-valid template text:

```html
<!-- {{ displayPrice }} -->
```

Interpolation inside an HTML comment is inert and must not become a rendered UI value.

Regression-first repair:

```text
099fabfcaeecbaf009b75052d20075745ee02437
fix: reject inert commented renders
```

## Blocker 3 — HTML tag/attribute interpolation

Compile-valid Angular shape:

```html
<div data-price="{{ displayPrice }}"></div>
```

The interpolation contributes an attribute value, not visible text. The existing rendered-value boundary described `ui-member-render` as a rendered/displayed UI value, so classifying attribute interpolation under that authority would overstate product behavior.

Regression-first repair:

```text
da5d23771ef8c9d58d0333d1f949e8d742210043
fix: require visible text interpolation
```

The authority filter now rejects an interpolation occurrence while it is lexically inside an HTML tag. The supported boundary is therefore active visible text interpolation, not arbitrary Angular interpolation semantics.
