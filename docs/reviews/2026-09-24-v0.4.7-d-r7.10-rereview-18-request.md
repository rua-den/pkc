## Why final repair is prefix-based fail-close

An intermediate repair tried to model semicolon/EOF/line-terminator/comment boundaries. Adversarial TypeScript 5.8.3 compilation proved additional valid ASI forms using LF, lone CR, U+2028, U+2029 and a line terminator inside a block comment.

The final repair therefore does not implement a partial ASI lexer. It recognizes unsupported alias/indirection whenever a declaration begins:

```text
const|let|var <identifier> = <identifier>
```

without requiring a particular terminator spelling.

This is intentionally conservative. If that identifier prefix continues into a call/member/binary or other expression shape that PKC has not proven as supported component-import topology, fail-close is acceptable. Unsupported inference must not create render/visibility authority.

Ordinary supported direct/local-array framework imports remain protected by positive regression.
